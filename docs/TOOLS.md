# Tools PatchCairn can coordinate

PatchCairn helps an assistant choose and coordinate official tools for an agreed task. Its records do not install software, grant administrator access, scan every file or execute commands stored in a plan. An assessment or diagnosis allows the selected evidence checks; changes follow the concrete plan the owner approves.

The [machine-readable tool catalog](../templates/tool-catalog.json) is the maintained reference for tool IDs, publisher, official URL, purpose, platform, required/optional status, permission and privacy limits, version-check meaning, installation approval and dated primary sources. It contains no actual computer inventory or permanent target-version list. Each source receipt has its own UTC check and access limits; the catalog's access review was completed on **2026-10-24T00:56:40Z**. Recheck support, installed capabilities and vendor guidance during a real session. A listed tool is not necessarily installed or connected.

## Choose an existing supported route

The assistant first identifies the real operating system, architecture, installation owner and available capabilities. A **required** tool is required only when the catalog's stated route is selected and supported. If it is absent, the assistant explains the gap or an appropriate official alternative. An **optional** tool is useful for a particular need, and ordinary assessment does not require installing it. Neither label authorizes an installation.

## Package-manager update routes

PatchCairn's built update routes use the package manager that owns the software: winget on Windows, Homebrew on macOS, and apt or dnf5 (Fedora 41 or later) on Linux. Each route reads what the manager offers through fixed read-only commands, binds the exact package, version, source and command into the reviewed action, and after approval runs only that step through a one-use ticket, without a shell and never while PatchCairn has administrator rights. On Linux the step runs in the owner's own Terminal. The route then reads the result again before it counts. See the [service contract](SERVICE_INTEGRATION.md).

Windows Update, macOS Software Update, firmware, Python and Node packages have no built route in this version; their actions hold. PatchCairn does not repair Windows itself. A downloaded installer is not an interchangeable route, and a small ordinary-file ZIP and restoration probe do not establish OS or package-state rollback.

## Optional archive and source tools

The backup helper uses an existing supported Python runtime's [standard-library ZIP support](https://docs.python.org/3/library/zipfile.html). A valid archive needs the separate manifest/hash/restore checks defined by the backup workflow. ZIP compression does not encrypt its contents, and `zipfile` cannot create encrypted archives. [7-Zip](https://www.7-zip.org/) is an optional archiver when a selected format needs it; it is not an assessment prerequisite. Use the exact official publisher ownership chain and reviewed artifact if installation is approved. Listing an archive does not authorize extracting it over other files.

[Git](https://git-scm.com/) and [GitHub CLI](https://cli.github.com/manual/) are optional for selected source/repository work or public upstream metadata. Ordinary host maintenance needs no account connection. Installing them, logging in, adding extensions, changing identity/remotes or publishing records is a separate decision. Never print tokens or inspect authentication files to check availability; private inventories/logs are not uploaded as a side effect.

The optional [Codex Security plugin](https://openai.com/business/plugins/codex-security/) assesses **code, repositories and changes**. It does not provide whole-host antivirus, operating-system integrity or complete installed-software vulnerability coverage. Use only when the owner selects that code scope and the host actually offers the plugin. Explain its permissions, model/service processing, private scan outputs and actual or unknown entitlement/usage cost before the appropriate connection or scan decision. A plugin listing is not proof of access, native support or permission to inspect unrelated code.

## Make a tool decision understandable

Before proposing an extra tool or consequential action, explain:

- What it will do and why the existing supported route is insufficient.
- The recommendation and alternatives, their benefits and drawbacks.
- Known money, download/storage and time/downtime costs; mark unmeasured cost or account entitlement **unknown**.
- Exact selected data/access, network or service processing, and where vendor/OS logs or installations can be written.
- Data preservation, practical reversibility, required recovery and how success will be checked.

The assistant records the owner's actual instruction against the reviewed plan and action IDs. Account permissions, automatic mode, an imported approval field or a tool's existence do not replace that instruction. The owner handles normal protected consent and authentication; PatchCairn never asks for passwords or bypasses a refusal. Deleting `work/` neither reverses approved installed changes nor removes vendor/OS records outside it.
