How a session works

Assessment, approval, an attempted action, and a verified result are separate steps.

An assessment can end after findings without making changes. Ask for the findings, remaining uncertainty, and the next useful choice.

  1. Choose a job. Start with the menu and select the kind of help you need.
  2. Agree scope. Select exact information or folders, exclusions, and privacy limits, then authorize assessment.
  3. Investigate. Gather bounded evidence and relevant official information.
  4. Explain findings. Understand meaning, confidence, unknowns, and the next useful check.
  5. Review a concrete plan. See targets, benefits, drawbacks, costs, recovery limits, and verification. Two independent reviews examine a change plan.
  6. Approve supported work. Choose the clearly identified actions you authorize in ordinary language.
  7. Verify and finish. Check actual results, explain remaining concerns, and choose what evidence and recovery material to retain.

How work proceeds

Guided
Review explanations at selected checkpoints. More opportunities to decide, with more pauses for your attention.
Automatic within an approved policy
Continue unchanged routine work within exact authorized boundaries. This needs clear limits and stop conditions.

When work begins

Now
Begin agreed work while you are available. An interruption or restart may need a separate decision.
Scheduled
Propose a later time. Actual schedule creation requires supported host capabilities and your authorization.
Some decisions always need attention.

Authentication, OS consent, missing required recovery, stale evidence, unknown outcomes, unsupported capabilities, and material scope changes never become automatic. A schedule grants no new permission and cannot silently resume paused work.

Commands you can use in chat

Use ordinary language or the PatchCairn: prefix. The assistant handles technical records; you do not need to edit JSON or transcribe identifiers.

Understand the boundaries

The workflow coordinates supported tools. It is not an antivirus, an operating-system sandbox, or a guarantee that every issue is found.

Private records stay local

Selected scope excludes browser data, passwords, saved chats, credentials, and unrelated projects from cleanup and broad discovery. Private records remain under owned work/ paths. This website has no computer access or maintenance controls.

Security and privacy

Recovery before permanent loss

Same-volume quarantine frees no disk space. Integrated purge requires exact verified original backup and restoration coverage, plus a separate permanent-loss decision. Unbacked quarantine can be reviewed for restoration.

Recovery and cleanup

Selected backup and update routes

The content-backup route is bounded to 16 MiB per file, 48 MiB selected content, and a 64 MiB archive. A ZIP is not encrypted or system rollback. Current update handoffs accept exact reviewed local MSI, PKG, or DEB artifacts; package-manager updates and OS/application repair routes remain held.
