# Security and updates

Work from this skill's repository root. Read [AGENTS.md](../../../AGENTS.md), the [pc-maintenance router](../pc-maintenance/SKILL.md), and [communication guidance](../../../references/COMMUNICATION.md). Building or opening PatchCairn does not authorize inspecting the current host.

Read [the security/update workflow](../../../references/SECURITY_UPDATES_WORKFLOW.md) for this mode. Use [source research](../../../references/SOURCES_AND_RESEARCH.md) for current claims and [compatibility guidance](../../../references/COMPATIBILITY.md) for runtimes, application ownership and target selection. Consult the matching [Windows/platform requirements](../../../docs/PLATFORM_SUPPORT.md), [Linux](../../../references/LINUX.md) or [macOS](../../../references/MACOS.md) reference only as needed.

Use [the conversation engine's current interface](../../../docs/WORKFLOW_ENGINE.md) to select `security_updates`, show the first menu, manage settings/checkpoints and render decisions. All commands use `PatchCairn: <command>`; preserve host commands such as `/help` and `/resume`. The engine supplies all available commands from the start. Guided/automatic control and now/scheduled timing are independent choices; neither automatically authorizes host changes or schedule creation. Read [the helper API](../../../references/HELPER_API.md) before helper calls; if an interface or gate is unavailable, hold that operation rather than invent flags or edit state.

Offer owner-authorized device-wide software/OS metadata, selected drives/folders or a particular component problem through the router's assessment descriptor. The agent may coordinate available verified read-only official tools; record actual covered categories and inaccessible/unsupported checks, without claiming a comprehensive scanner or weakening helper gates. Additional local content and LLM disclosure remain separate selections. Identify installation owner, architecture, scope, channel, supported branch and observed version before choosing a compatible target. Keep project-pinned, application-bundled and needed side-by-side runtimes distinct. Research current vendor advisories, releases and relevant news; distinguish applicability, unknown conditions, support status and exploitation evidence. A newer version or empty update list is not a security clearance.

The coordinator owns state, UI and mutations. Use a matching platform specialist and source researcher for bounded independent questions. Before a concrete change, obtain two independent adversarial reviews: compatibility/data safety and evidence/security correctness. Their approval does not substitute for the owner's actual consent or OS permissions. If independent reviewers are unavailable, retain the change hold and finish useful assessment. Roles describe work, not certifications or unavailable host capabilities.

Make each proposed action precise: installed target, source/artifact provenance, command or supported UI action, prerequisites, dependency/data effects, recovery limits, verification and restart policy. Explain the recommendation, benefits, drawbacks, actual or unknown money/time/storage costs, privacy effects and reversibility in ordinary language. Freeze the plan and bind the owner's real instruction to its hash and selected action IDs. Assessment consent, imported approvals and automation settings cannot supply change authority.

Execute only approved actions through verified official tools, one transaction at a time, after fresh precondition checks and a durable engine begin-operation receipt. The assistant coordinates the tools; PatchCairn records do not execute arbitrary plan strings. Hold on source drift, failed integrity, locks, partial/unknown results or changed scope. Preserve receipts; never retry a consumed action automatically. Checkpoint before interruption/restart, honor pause immediately for new work, and reconcile actual outcomes before resuming.

For fixed local-artifact update handoffs, bind the exact owned installer path/native identity/hash and reviewed publisher/signature/version/architecture/channel before the coordinator's actual official call; use only the current catalog's fixed arguments and actual owner/OS consent. A package-manager selection does not prove consumption of separately inspected bytes and holds when unenforceable. Current integrated OS/app repair stays held without typed recovery for the exact component; a file ZIP is not OS rollback. Read the mode workflow and [service contract](../../../docs/SERVICE_INTEGRATION.md) for supported routes and limits.

Verify installed identity, activation/restart state, relevant behavior and the specific security claim separately. Report remaining vendor dependencies, compatibility holds and unassessed scope. Store generated evidence, downloads and reports under owned `work/` paths; this does not confine authorized source targets to work. Preserve default browser/session/project-content exclusions, exact relevant local-read exceptions and separate disclosure selections; credential values remain excluded. Use [the tool catalog guide](../../../docs/TOOLS.md) to explain required versus optional tools without installing prerequisites silently.
